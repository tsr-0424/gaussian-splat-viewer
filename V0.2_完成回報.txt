2. Performance Monitor 如何運作

requestAnimationLoop 以時間戳記量測 frame interval；固定大小 ring buffer 保存約兩秒樣本，維護總和，避免每 frame 排序或讀取 GPU 資訊。
FPS = 1000 / 平均 frame interval；Frame Time 也是此平均值，不是 GPU 計時。
每 500 ms 更新 HUD／面板；面板關閉時不更新面板文字。
只有模型 ready、分頁可見時記錄；resize／DPR 改變、分頁切換會清除歷史；超過一秒的排程中斷會重設統計。

面板顯示：
- FPS、Frame Time、實際 Canvas Resolution、Viewport Size。
- devicePixelRatio、Renderer Pixel Ratio、品質模式與有效 preset。
- Spark numSplats（此模型 396,047）。
- WebGL／WebGL2、WebGPU API 是否存在；實際渲染是 WebGL2。
- GPU Renderer 與 hardware-likely／software／unknown。
- 可用時的 JS heap、RAM hint；Three.js texture／geometry 數量。

GPU 名稱僅初始化時查詢一次。Memory 缺少 API 時顯示 Unavailable；JS heap 不代表完整 GPU／WASM／Worker 記憶體，資源計數也不是 GPU bytes。
Performance Panel 與 Benchmark 僅開發模式載入；正式 dist 已確認不含面板／benchmark 文案與模組。

3. Adaptive Quality 邏輯

預設 AUTO；不使用 userAgent 選品質。
- 疑似 software：使用者先選低畫質才載入，該次執行最高 LOW。
- GPU 資訊不可見：MEDIUM 起步。
- 可見且未匹配 software：一般像素量 HIGH 起步；預期 framebuffer 大於 200 萬像素時 MEDIUM 起步。

只在樣本至少五筆、涵蓋至少一秒、模型 ready 且分頁可見時判斷兩秒 rolling average：
- 低於 28 FPS 持續 4 秒：降低一級。
- 高於 55 FPS 持續 10 秒：提高一級。
- 28–55 FPS：維持品質。
- 啟動完成、每次切換、resize 或分頁恢復後：12 秒 cooldown。
- 單次短暫 drop 不切換；手動 HIGH／MEDIUM／LOW 不自動改動。

此設計以穩定約 30–60 FPS 為目標，不會限制高效能硬體只能跑 60 FPS，也不能保證極弱硬體一定達到 30 FPS。
Benchmark 期間暫停 AUTO 與操作；完成／取消後恢復原模式。

4. 如何判斷 software renderer

先建立 WebGL2 context，另測 WebGL 可用性；Viewer 使用同一個已檢測的 WebGL2 context。
瀏覽器允許時讀 WEBGL_debug_renderer_info 的 unmasked renderer。
匹配 SwiftShader、Microsoft Basic Render Driver／Display、llvmpipe、softpipe、software rasterizer／renderer、lavapipe、swrast、WARP。
沒有針對 NVIDIA 寫死；Intel、AMD、Apple、NVIDIA 均正常接受。
GPU 名稱被隱私設定隱藏時標示 unknown，不把它誤判為 software。

疑似 software 時顯示：
「目前瀏覽器似乎沒有啟用圖形硬體加速，3D 模型可能無法流暢顯示。」
提供「低畫質模式」與「重新檢測」；重新檢測會重新整理並建立新 context。
這是 renderer 字串的啟發式判斷，瀏覽器不保證提供完整硬體加速資訊。

5. HIGH／MEDIUM／LOW 實際設定

HIGH：DPR 上限 2；framebuffer 預算 4,000,000 pixels。
MEDIUM：DPR 上限 1.25；預算 2,000,000 pixels。
LOW：DPR 上限 0.75；預算 1,000,000 pixels。

有效 ratio = min(devicePixelRatio, preset DPR cap, sqrt(pixel budget / CSS viewport area))。
最低數值保護為 0.1；resize、瀏覽器縮放或換 DPR 時重新計算。
小視窗 DPR=1 時 HIGH 和 MEDIUM 可能相同，避免不必要的 supersampling。
所有 preset 只影響畫布解析度，Spark Gaussian 資料與數量不變。
未來 LOD／Splat reduction／SH／progressive loading 可從 QualityPresets 與 Viewer.setQuality 擴充，目前未啟用。

6. Desktop 實測 FPS

測試環境：Windows，Codex 內嵌 Chromium（userAgent Chrome/154.0.0.0），GPU NVIDIA GeForce RTX 4070，ANGLE Direct3D11。
模型：新福里，396,047 Gaussian。
CSS viewport：1920 × 1080；devicePixelRatio：1。
固定重設視角，各 preset 暖機 3 秒、收集約 8 秒 frame intervals。

品質     FPS       Frame Time     Canvas Resolution   Renderer Ratio
HIGH     74.993    13.335 ms      1920 × 1080         1.000000
MEDIUM   74.993    13.335 ms      1885 × 1060         0.982093
LOW      74.993    13.335 ms      1333 × 750          0.694444

各 preset 的 p95 frame time 約 13.4 ms。Gaussian count 均為 396,047。
516 × 452 小視窗三種品質同樣約 75 FPS；LOW resolution 為 387 × 339。
三種品質幾乎相同，可能受 vsync／瀏覽器排程限制；不能據此宣稱 LOW 對所有模型都沒有收益。
這是本機固定視角的桌面實測，不是 standalone Chrome／Edge／Firefox／Safari 全平台實測。

Benchmark 使用方式：npm run dev → Performance 或 P → Run HIGH / MEDIUM / LOW。
約 33 秒後可 Export JSON，包含 FPS、frame time、p95、解析度、ratio、GPU、browser、模型與時間。
resize／切換到背景會取消；software renderer 只測 LOW。
