# V0.2 可重用解法與維護紀錄

- 效能模組位於 `src/performance/`，可用於後續 Three.js／Spark 專案；品質僅改 resolution。
- Spark 2.3.0 decoder 可能 reject 字串，不能直接寫 error.code。統一轉 Error；DOMException 的 code 唯讀，AbortError 保留原樣。
- Fetch 模型時 Accept: application/octet-stream，避免 Vite SPA fallback 將缺少模型回傳成 index.html（200），誤分類為格式錯誤。
- Benchmark 內部換品質也會觸發 resize callback，需 transitioning guard；外部 resize／背景分頁才取消。
- 預設 DPR=1 的小視窗 HIGH／MEDIUM 可以相同；比較前必須一起記錄 effective ratio 與 canvas resolution。
- 75 FPS 可能是 vsync ceiling；固定視角相同 FPS 不代表所有模型／移動路徑都一樣快。
- GPU renderer extension 與 JS heap 是可選 API；未知值不可誤判為 software GPU，也不應冒充完整 GPU memory。
- 本地 debug triage Worker 在 Windows CP950 讀 Node Unicode 輸出會失敗，使用 Python `-X utf8`。最後五行通常只有 stack 尾巴，可能使 coder 無法辨識根因；保留 Worker 流程，CEO 以 source／測試語意做決策，未直接讀完整日誌。
- Screenshot 交由本地 vision Worker 判讀；其對 1920 viewport 的 panel 描述與 DOM 不一致，診斷欄位以 DOM 與 benchmark 數據為準，不把視覺模型描述當量測。

回歸測試：`npm test`。後續程式改動後依涉及模組執行，避免重複耗費不必要的 render／看圖迴圈。
